# Original composition: visible SVG is the executable score

This is a provenance contract, not an artistic recipe: invent any vocabulary and synthesis. Do not copy the optional example's melody, form, palette, density or element types. Builder scripts are welcome. The complete audible arrangement lives in visible SVG marks, and every sound-producing element carries data-audible="true". Decode timing, pitch and duration from each mark's geometry (position, size, path); attributes carry only controls such as voice, velocity and pan. Never store the score in metadata, base64, hidden elements or render.py.

Studio removes every data-audible mark, reruns render.py on a sandboxed copy of the directory and expects finite silence. The renderer must therefore handle an empty score (guard peak normalisation against division by zero), write outputs relative to its own file, and only read the saved score.svg: keep score-building code in a separate script, never in a render.py that regenerates the score.
